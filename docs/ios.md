# iOS에서 쓰는 법 — 웹, 사이드로드, 네이티브

질문이 "웹으로 되나? 앱으로 해야 하나? 앱스토어 없이 설치도 되던데?" 였으니 순서대로 정리합니다.

## 1. 먼저 웹으로 (추천)

Safari에서 배포 주소를 열고 **공유 → 홈 화면에 추가**. 이걸로 끝입니다.

- 아이콘이 생기고 주소창 없는 전체 화면으로 뜹니다 (`display: standalone`).
- **카메라 됩니다.** iOS 14.3부터 홈 화면에 추가한 웹 앱에서도 `getUserMedia`가 동작합니다.
- **HTTPS 필수.** `http://`로 열면 카메라가 아예 안 잡힙니다. GitHub Pages면 자동으로 HTTPS입니다.
- 서명도, 7일 만료도, 심사도 없습니다.

### iOS에서만 걸리는 것들

| 항목 | 상태 |
|---|---|
| 카메라 | ✅ (홈 화면 추가 + HTTPS) |
| 화면 꺼짐 방지 (Wake Lock) | ✅ iOS 16.4+ |
| 푸시 알림 | ⚠️ **홈 화면에 추가했을 때만**, iOS 16.4+ |
| 진동 (`navigator.vibrate`) | ❌ 지원 안 함 — 소리/음성으로 대체됩니다 |
| 무음 스위치 켠 채 소리 | ⚠️ 막힐 수 있음 — 먼저 `설정 → 경고 테스트`로 확인하세요 |
| 백그라운드에서 계속 감시 | ❌ 앱을 나가면 멈춤 |

앞의 두 개(진동·무음)는 이 앱이 소리·음성·전체 화면 경고를 같이 쓰는 이유입니다.

### 폰에서 개발 중인 걸 열어 보려면

`localhost`는 보안 컨텍스트로 인정되지만 `192.168.x.x`는 아닙니다. 그래서 개발 서버에 TLS 모드를 넣어 뒀습니다.

```
npm run dev -- --https      # 자체 서명 인증서를 만들어 https://<내부IP>:8443 로 서비스
```

폰 Safari에서 그 주소를 열면 경고가 뜹니다 — `고급 → 방문`으로 한 번만 통과하면 됩니다.
(자체 서명 인증서에서는 서비스 워커 등록이 막힐 수 있습니다. 오프라인 캐시까지 확인하려면 실제 HTTPS 배포에서 테스트하세요.)

## 2. 앱스토어 없이 설치 (사이드로드)

카메라 방식이라면 웹 대비 얻는 게 거의 없습니다. 그래도 정리하면:

| 방법 | 비용 | 만료 | 필요한 것 |
|---|---|---|---|
| Xcode + 무료 Apple ID | 무료 | **7일**, 앱 3개 제한 | Mac |
| Apple Developer Program | 연 $99 | 1년 | Mac |
| AltStore / SideStore | 무료 | 7일, 자동 갱신 | 같은 네트워크의 PC 또는 SideStore 서버 |
| Ad Hoc 배포 | 연 $99 | 1년 | 기기 UDID 등록 (최대 100대) |
| 대체 마켓플레이스 | 다양 | — | **EU 거주자만** |

7일 만료는 생각보다 거슬립니다. 습관 교정용으로 매주 재설치하는 앱은 결국 안 쓰게 됩니다.

## 3. 네이티브가 진짜 필요해지는 지점

웹으로 **안 되는** 건 딱 하나, **화면을 안 보고 있을 때의 감시**입니다.
그리고 그건 카메라로 풀 문제가 아닙니다 — 주머니 속 폰은 아무것도 못 보니까요.

여기서 답은 **Apple Watch**입니다. 손목 가속도계·자이로는 폰을 안 보고 있어도 손이 입으로
올라가는 동작을 잡습니다. 실제로 상용 제품(Keen, HabitAware 같은 진동 밴드)이 쓰는 방식도 이쪽입니다.

- `CMMotionManager`로 손목 가속도/자세를 읽고, 팔을 드는 동작 + 입 높이에서 유지되는 패턴을 분류합니다.
- Core ML에 작은 분류기를 올리거나, 임계값 기반으로 먼저 시작해도 됩니다.
- `WKHapticType.notification`으로 손목을 톡 칩니다 — 소리보다 훨씬 덜 민망하고 회의 중에도 씁니다.
- 워치 앱은 배경 실행 예산이 따로 있어서 세션 유지가 됩니다.
- 대신 Mac + Xcode가 필요하고, 실기기 테스트에는 위의 서명 제약이 그대로 붙습니다.

**권장 순서:** 이 웹 앱으로 책상에서 며칠 써 보고 → 감지가 실제로 쓸 만한지, 경고가 습관을 끊는지
확인한 다음 → 그때도 "자리 밖에서도 필요하다" 싶으면 워치 앱으로 넘어가세요.
튜닝한 임계값과 기록이 그대로 설계 근거가 됩니다.

## 배포

이미 올라가 있습니다: **https://trash-traco.github.io/sontop/**

폰 Safari로 그 주소를 열고 **공유 → 홈 화면에 추가**하면 끝입니다.

`main`에 푸시할 때마다 `.github/workflows/pages.yml`이 테스트를 돌리고, 통과하면
앱이 서빙하는 파일만 골라 `gh-pages` 브랜치로 푸시합니다. 그 뒤는 GitHub의
`pages build and deployment`가 알아서 게시합니다. 설정 화면을 건드릴 일은 없습니다.
